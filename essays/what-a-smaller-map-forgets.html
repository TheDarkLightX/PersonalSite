Essay 15 · Representation and memory

What a Smaller Map Forgets

One bit can tell us a solution exists. Carrying it out may need the details we threw away.

Dana Edwards · November 16, 2026

Imagine a puzzle with four lights and three buttons. You want only the last light on. A helper looks at the panel and tells you, correctly, “Yes, you can get there.” Then the helper covers the lights and hands you a card with one word on it: YES.

You ask which button to press. The card has no answer.

That missing instruction turns out to have an exact price. For this puzzle, a perfect yes-or-no summary needs only two labels. A summary that can also supply a correction, after the original panel has been hidden, needs at least nine. A label is simply a code that several starting patterns may share. We can prove both numbers.

I found this separation while extending the representation experiments in my paper, Positive Seeds, Exactness, and Certificates for Operation Search. The paper studies what a restricted set of operations can build. For this essay, I asked what happens when we replace a detailed problem with a smaller description. The answer depends on what we will ask that description to do.

A puzzle small enough to see

Write an unlit light as 0 and a lit light as 1. Our goal is 0001. Each button flips a fixed set of lights: on becomes off, and off becomes on.

A0011Flip the last two.
B0101Flip the second and fourth.
C1111Flip all four.

Start at 0010. Press A and you reach 0001. Start at 0001 and you should do nothing. Both starts deserve a YES, but they need different corrections.

Pressing a button twice cancels its effect. The order of the buttons does not matter either: each light only cares whether it was flipped an odd or even number of times. Any long button sequence therefore has the same effect as some choice of A, B, and C, each used at most once.

There are eight such choices. They produce eight different patterns of flips. Every one flips an even number of lights.

In the demonstration below, the decoder is the part that tries to turn the summary back into an instruction. Try giving it access to the original lights.

The one-bit shortcut

Count the lit lights. You only need to remember whether the count is odd or even. Mathematicians call that distinction parity.

Flipping two lights changes the count by minus two, zero, or plus two. Flipping all four changes a count of k to 4 − k. Either way, odd stays odd and even stays even. Our goal has one light on, so an even starting pattern can never reach it.

For these particular buttons, every odd starting pattern can reach the goal. Compare the start with 0001 and mark the places where they differ. There will be an even number of marks, and the eight button choices give every even pattern of flips.

We can now replace sixteen starting patterns with two labels: NO for even, YES for odd. A one-bit answer settles the question for every possible start and every possible length of button sequence.

The computer search recovered this shortcut. I used an existing program from my private research that proposes different ways to describe a problem: a shift synthesizer. ZAL checked its proposed translations. It tried 32 ways to select some of the four bits, add them, and keep only odd or even, optionally reversing the result. Paired with two possible ways to read the output, that made 64 candidates. Only two passed: count all four bits, or use the same count with the labels reversed.

This was a complete search of that small family. It was not a search of every imaginable way to compress a problem. The stronger minimum claims below have separate proofs.

Why the instructions cost more

Now ask the helper for a correction: which lights must be flipped to reach 0001? The answer must be recovered from the smaller description alone. The helper cannot look at the original panel again, and there is no hidden record of it.

There are eight solvable starting patterns. Each needs a different correction. For example, 0001 needs no flips, while 0010 needs the last two lights flipped. Giving those starts the same label would force the decoder to use the same correction for both.

That cannot work. Take any two different starting patterns and apply exactly the same flips to both. Wherever they differed before, they still differ afterward. They cannot both become 0001.

So the eight solvable starts need eight separate labels. The eight impossible starts can share a ninth label, NO. They cannot share a label with a solvable start: that would erase the distinction between having an answer and having none.

Nine labels are necessary, and nine are enough. Store each solvable start separately and put all impossible starts together. Each solvable label then points to its unique correction.

Two labels fit in one bit. Nine labels require four bits in a fixed-width code, because three bits offer only eight combinations. We compressed the yes-or-no question from four bits to one, yet supplying a correction from the summary alone takes four again. This counts information, not running time.

The general counting argument is just as short. If there are m solvable cases whose acceptable answers never overlap, they need m distinct labels. If the same representation must also cover an impossible case, it needs one more. Lean checked that argument and its application to this puzzle. The proof allows the reduced solver to offer several possible answers; every offered answer still has to work.

Open the cover again

Suppose we give the decoder its YES card and let it see the original lights. It can compare the panel with the goal and find the correction immediately.

For 0010 and 0001, the last two positions differ. Flip them. For a panel already showing 0001, none differ. Leave it alone.

correction = start ⊕ goal⊕ marks the positions where two patterns differ.

Applying the correction cancels the starting pattern:

start ⊕ (start ⊕ goal) = goal

The one-bit decision can now be part of a working system, because the information needed to act is still available elsewhere. We have not squeezed a full correction into YES. We have changed what the decoder is allowed to see.

ZAL accepted this version and rejected the version that had forgotten the original input. A deliberately wrong correction was rejected too. The failed cases are useful records: they tell a later search exactly which assumption it must repair.

Back to the paper’s one-button calculator

The paper begins with a more unusual machine. It takes two real numbers, raises e to the first, and subtracts the natural logarithm of the second:

F(a, b) = ea − ln(b)The second number must be positive, at every step.

You may copy a starting number and reuse the machine’s answers. With 1 available, combinations of this single operation can perform ordinary arithmetic. With any positive starting number, finite expressions can get as close as you ask to any real target.

A four-operation pattern supplies the crucial step. After an initial calculation puts the value above 1, repeating the pattern brings it closer and closer to 1 while keeping it strictly above. That gives arbitrarily accurate substitutes for 1, from which the approximation proof builds further arithmetic.

Exact equality asks more. This particular approach never lands on 1 after finitely many repeats. Some other expression might. The paper does not settle whether starting from 2 can produce exactly 1.

The finite part of the paper changes the view from expressions to their answers. A program with two on/off inputs has four possible input pairs. Write its four answers as four lights. The first input has pattern 0011; the second has pattern 0101. AND, which says yes only when both inputs are on, has pattern 0001.

XOR flips positions where another pattern contains a 1. NOT flips all four. Starting from the input patterns and constants, any expression made with XOR and NOT has an even number of ones. AND has an odd number. That proves the entire language cannot build AND, however large its expressions grow.

The puzzle extends that example by allowing all sixteen starting patterns, including the eight odd ones the original language cannot generate. Its buttons add the first input, add the second, or flip everything. This change makes it possible to compare successful construction with impossibility in the same small world.

That is the extra result for the essay: the paper’s small impossibility certificate is a perfect decision summary here, while a correction needs distinctions that the summary deliberately erased.

What a search should remember

If a starting pattern is even, a search does not need to keep trying longer button sequences. It can save the reason: these buttons preserve oddness or evenness, and the goal is odd. One proof rules out infinitely many attempts.

The reason belongs with its conditions. Add a button that flips just one light and the argument fails. Change the goal to an even pattern and the old YES/NO labels reverse. A remembered failure is useful only when the new problem still satisfies the assumptions that made it a failure.

For successful cases, the useful memory may need to be richer. A record saying “solvable” can prune a search or answer a question. To execute a solution later, we must retain a correction, enough information to reconstruct one, or access to the original input.

I would use this distinction when designing a synthesis system’s handoffs. Before shrinking a problem, write down the question the smaller representation must answer and what the next stage may still inspect. Then check that particular promise. A representation that is excellent for rejecting impossible tasks may be insufficient for carrying out possible ones.

Return to the covered panel. The YES card was accurate. To press the right button, you still need to know which lights are on.

Evidence and further reading

This is an additional checked example relative to the paper, not a claim to have discovered a new general theory of compression. The distinction between a decoder that can access the original input and one that cannot is established in the theory of computational reductions. Brattka, Hendtlass, and Kreuzer describe it in Definition 2.2 and the paragraph following it. Our finite contract additionally requires solvability and impossibility to be preserved on all sixteen inputs.

The actual search used the existing synthesizer and ZAL checker. The public independent Python replay uses no private libraries and checks all sixteen starts, all 64 candidates, and the incompatible corrections. Its complete results reproduce the search’s accepted maps and examples. The nine-label representation was constructed and checked; its minimality comes from the proof, not from an exhaustive search of all representations.

The Lean source proves the general label bound, the exact nine-label result for the correction relation, and the two-label decision bound. It compiled with Lean 4.24.0 and the pinned Mathlib version in the replay instructions, without admitted proofs or custom axioms. The axiom report records the standard foundations used. The finite move closure and the browser illustration are checked by executable replay; this is not a proof of the ZAL implementation or of the JavaScript interface.
