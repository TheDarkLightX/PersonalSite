Essay 10 · Computation and formal methods

Neural networks as fuzzy lookup tables?

Weights, tables and compilation as ways to construct a computation.

Dana Edwards · November 2, 2026

I have always regarded artificial neural networks as computations implemented in software. I reached that conclusion by examining them at several levels of abstraction: functions mapping inputs to outputs, compositions of those functions, and implementations using numerical parameters. An artificial “neuron” is a computational unit; its name does not make it a biological neuron.

I also regard training as a form of programming through examples and an objective. Programming by example is an established part of program synthesis, the automatic construction of programs from requirements. Examples can provide those requirements, although they often leave the intended behaviour partly unspecified. Neural parameter fitting and symbolic program search use different methods, but I see both as ways of constructing computations.

The language of “training” can encourage an anthropomorphic explanation of this process. The familiar principle of “garbage in, garbage out” still applies. Misleading examples, unsuitable objectives and flawed assumptions can produce unreliable outputs. Data quality, program construction and checking all remain engineering concerns.

Weight-space programming supplies a direct example: the authors report a language model generating and editing another network's weights without using gradient descent, the usual method of adjusting parameters using calculated directions of improvement. The editing model was already trained. QwenPU takes a compiler route, adding layers that implement a processor while preserving the base model's weights. A small language model runs as a program on that processor.

Weights can therefore be fitted, edited or compiled. I describe the resulting mechanism as programmed computation. Calling it “thinking” is an interpretation of that mechanism; programmability alone does not settle every philosophical definition of thought.

These experiments put my longstanding view into practice: learned computations can be represented as layered lookup tables and executed in Tau Language, where stated requirements can be checked.

A lookup table lists outputs for inputs. Any deterministic function on a finite set of permitted inputs has a complete table representation. A neural network with fixed parameters, bounded digital inputs and precisely specified execution rules therefore has one too. Relevant state and randomness must be fixed or included in the input.

Weights and lookup tables can do the same thing: the network's operations and weights determine a function, and a table can encode exactly the same outputs. This equivalence does not require the two representations to have the same storage or execution costs.

With 64 input bits, listing every combination requires 2⁶⁴ rows. Layers can help when the function has useful structure: small tables feed their outputs into other small tables, avoiding the need to list the entire computation at once. Learning then selects or adjusts those tables using examples and a training objective. Layers provide the architecture; a training procedure supplies the learning process.

NeuraLUT converts trained neural subnetworks into tables for hardware execution. My focus is on executing learned table networks in Tau and checking their behaviour against explicit requirements.

The phrase “fuzzy lookup table” is an analogy for how a network approximates a desired mapping. It should not obscure the stronger mathematical point: once a deterministic computation and its finite input domain are fixed, an exact table representation exists.

A network of 40 tables, fixed after training, was checked in Tau and ZenoFCIS against a separate implementation of the same tables on all 256 permitted input pairs. The implementations agreed, including on cases where the learned answer was wrong. This checks the frozen network's execution, not whether freezing always preserves the smooth computation used during training.

The task was to determine whether A was at least as large as B. For A = 0 and B = 1, the selected network returned true. Deterministic execution preserved the mistake.

A fixed table gives a reproducible answer; it does not make the answer true or eliminate hallucinations by itself. A classifier restricted to labels or a game policy restricted to moves still needs evidence that its outputs satisfy the relevant requirements.

In a game, selecting a legal move and never losing are different properties. Each needs its own check, with the starting conditions and permitted opponent behaviour stated clearly. Formal methods, techniques for expressing and checking requirements mathematically, help make those distinctions precise.

I want to investigate how depth, table size and wiring affect both learning and checking. There is no established best layer count in these experiments. A useful next study would compare several depths with the same total table budget, then measure accuracy, execution cost and checking cost independently.

The experiments give concrete support to a view I already held: neural networks are software computations, and training constructs their behaviour. I want to extend that work by making both the computed function and the evidence for its required behaviour explicit.

Research note

The pilot results come from my V4 manuscript of How Far Can Layered Lookup Tables Go?, dated 2 November 2026. The public preprint record contained the earlier V1 file when checked on that date. NeuraLUT is by Marta Andronic and George A. Constantinides, version 2, 2024.

For programming by example, see Sumit Gulwani's Synthesis from Examples, based on the WAMBSE 2012 keynote. Treating neural training as a form of programming is my framing of the relationship, not a claim that every synthesis method and neural training algorithm are identical.

Sparks of Weight-Space Programming is by Rikiya Takehi, Jayden Teoh, Alex Zhang and Omar Khattab, 2 November 2026. QwenPU is by Divyansh Agrawal; the linked documentation is pinned to its 31 October 2026 revision. Their experimental results are author-reported and were not independently reproduced for this essay.
